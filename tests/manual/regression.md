## 用例

| G7 删除/序号：集合/持久化改动 | 建5点，删首/中/末，撤回，保存；删光再建点；检查取消新点及取消本条更改 | 有效点连续1…N，待删除区不占编号，撤回恢复原顺序；删光后新点#1；舞台/列表/辅助名称一致，ID不变 | 原R10，替代旧“编号不重排/不复用”的用户界面预期 |
| G8 完整版本：保存/历史/迁移改动 | V1保存5点，V2修改并删除，V3只改大小；逐版查看，展开/收起本次变化；无变化检查保存按钮；超20版时加载更早项 | 每次有效保存一个固定版本，重试不重复；默认完整集合，无继承文案及删除幽灵点；比较可看大小变化和上一版删除点；每版连续编号独立、全部保留 | 原R5/R6/R11及W13；比较按ID关联，不把显示序号当身份 |

| G10 离开保护：导航/昵称改动 | 带修改从当前/历史页返回图库、换图或切昵称，分别选择留下/放弃/保存并继续；留空说明重复；历史浏览后返回当前 | 目标只执行一次；失败不离开；输入保留、历史不覆盖草稿；返回按钮可见且不挤标题/保存按钮 | 原R9/W6/W9；防止导航导致静默丢输入 |
| G11 刷新/缓存：会话/协议改动 | 同标签页带未保存输入刷新；普通新窗口仅用链接打开；按M3限制站点存储；结束恢复许可 | 同标签页尽力恢复、默认收起；新会话仅正式数据；缓存失败不冒充保存或清空当前输入 | 原W7与当前M3，替代旧P3 Blob恢复/离线纯本地界面 |
| G12 请求恢复：请求/保存状态改动 | Offline保存后Online重试；若出现结果未知，用原请求确认；两独立窗口同基线编辑，A先保存再让B保存 | 输入保留、不伪报成功；未知载荷冻结，同请求不重复；旧基线拒绝且不自动覆盖，不宣称自动合并 | 原W10及适用P4保护；普通离线不等于服务提交后响应丢失，后者主要用自动注入覆盖 |
| G13 文件/服务：上传/构建/存储改动 | 按M1验证样本，按M4使用同测试目录切生产/重启；存储改动时用已停止的测试目录副本演练备份恢复 | 错误明确且可重试；正式图/版本跨重启、恢复副本可读取；不备份活动SQLite的单个db文件，不碰真实目录 | 浏览器解码和生产页面不能由构建/API代替；故障与数据恢复需保留人工边界 |

## 选择范围与记录

小改动执行G1及对应行；涉及保存/共享schema/迁移时增加G5–G13；交付前跑全部适用项。缺样本、缺第二设备或未命中故障的分项记录未执行，不能写通过。

记录：`日期 / 改动或spec / G编号 / 通过-失败-未执行 / 浏览器与宽度 / 现象 / requestId`。若发现真实缺陷，回填对应spec的BC记录；纯粹列入回归不重新打开已通过需求。

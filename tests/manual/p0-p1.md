# P0–P1 手动测试集合

范围：启动、状态页、服务恢复与退出。当前没有图片上传或标记功能。以下为待用户复验项，不代表本轮已人工通过。

## 准备

在仓库根目录使用 PowerShell，Node 24.x；先执行 `npm ci`。本机 3000 曾被其他应用占用，这里显式使用 3102，避免中断其他服务；如已占用，请另选空闲端口。

```powershell
$env:HOST = '127.0.0.1'
$env:PORT = '3102'
$env:VITE_PORT = '5173'
$env:DATA_DIR = Join-Path (Get-Location) 'tests/.tmp/manual-p0-p1'
npm run dev
```

开发页面为 http://127.0.0.1:5173，后端为 http://127.0.0.1:3102。所有试验只使用上述临时目录。

## 必测条目

| 条目 | 怎么测试 | 预期结果 | 为什么测试 |
|---|---|---|---|
| M1 开发页面 | 按准备步骤启动，打开 5173 页面；点击“重新检查” | 显示“审图打点”“服务已就绪”和“图片标注功能尚未实现”；点击后仍正确就绪 | 确认真实浏览器加载、前端与代理链路，而非仅 API 正常 |
| M2 检查中与超时 | DevTools → Network 将速度设为 Slow 3G，点击重新检查；随后切为 Offline 再点一次 | 检查时显示“检查中”、按钮禁用；失败或约 5 秒超时后显示“服务不可用”，按钮恢复 | 检查等待状态和超时，避免页面一直卡住 |
| M3 网络恢复 | 恢复 Network 为 No throttling / Online，再点重新检查 | 恢复“服务已就绪”，不必刷新页面 | 检查用户能从网络故障恢复 |
| M4 布局与键盘 | 将窗口宽度改为约 375、860、1280；按 Tab 聚焦按钮，按 Enter | 无页面横向溢出；文字可读；按钮有焦点提示并能触发检查 | 视觉布局、可读性和键盘可用性需真人确认 |
| M5 开发退出 | 开发终端 Ctrl+C；运行下方端口检查，再执行原来的 npm run dev | 5173/3102 无残留监听，新启动正常；日志含停止事件 | 验证真实终端的信号处理，补充自动测试的 IPC 退出覆盖 |
| M6 生产运行 | Ctrl+C 停开发；执行 npm run build，再 npm run start；打开 3102 页面 | 只运行 Node 即可看到同样页面和就绪状态，无需运行 Vite | 确认构建交付与开发模式行为一致 |
| M7 停服重试 | 保留生产页面，终端 Ctrl+C 后在页面点重新检查；同终端重新 npm run start，再点重新检查 | 停服后不可用；重启后就绪 | 覆盖真实服务断开与恢复，不用模拟响应替代 |
| M8 API 与排错 | 生产服务运行时，浏览器打开 /api/health、/api/ready、/api/not-found；DevTools 查看未知接口的响应与响应头 | 前两项为 ok/ready；未知接口为 JSON 404，code=API_NOT_FOUND，正文 requestId 与 X-Request-Id 相同 | 确认可见错误便于用户定位请求，不回落到 HTML |
| M9 复用数据库 | 停服后用下方只读命令记下迁移记录；使用同一 DATA_DIR 启停两次，再查询 | 迁移条数、checksum、applied_at 不变；app.db 保留，无图片/标记表 | 确认正常运行时没有重置数据库或重复迁移 |

端口检查（服务停止后无输出为预期）：

```powershell
Get-NetTCPConnection -LocalPort 5173,3102 -State Listen -ErrorAction SilentlyContinue
```

M9 只读检查：

```powershell
node --input-type=module -e "import Database from 'better-sqlite3'; import path from 'node:path'; const db = new Database(path.join(process.env.DATA_DIR, 'app.db'), {readonly:true}); console.log(db.prepare('SELECT * FROM schema_migrations').all()); console.log(db.prepare('SELECT name FROM sqlite_master').all()); db.close();"
```

## 可选的启动失败复验

以下已由自动测试覆盖，只有排查本机环境问题时才需要手动补验。使用单独终端，不改变正在正常运行的实例。

| 条目 | 怎么测试 | 预期结果 | 原因 |
|---|---|---|---|
| M10 非法配置 | 设置 `$env:PORT='invalid'` 后 `npm run start`；再恢复端口，设置 `$env:DATA_DIR='relative'` 后重试 | INVALID_PORT / INVALID_DATA_DIR，`$LASTEXITCODE` 为 1，不启动服务 | 确认本机配置错误明确可见 |
| M11 端口冲突 | 保持生产实例占用 3102；另一终端设置 PORT=3102、DATA_DIR 为 tests/.tmp/manual-p0-p1/second 的绝对路径，再 start | 第二个实例 PORT_IN_USE、非零退出；首个实例继续可访问 | 确认不静默换端口，也不终止其他服务 |

目录拒写、迁移损坏和缺少构建由正式集成测试在隔离副本中验证，不要求人工修改真实数据库、迁移文件或 dist。Windows ACL 拒写尚未实机演练，不宣称全部权限故障已覆盖。

## 结束与反馈

停止所有本次启动的终端服务后，清理专用手动数据；这会删除本次验收数据库，不影响默认用户数据：

```powershell
$manualTarget = [IO.Path]::GetFullPath((Join-Path (Get-Location) 'tests/.tmp/manual-p0-p1'))
$allowedParent = [IO.Path]::GetFullPath((Join-Path (Get-Location) 'tests/.tmp')) + [IO.Path]::DirectorySeparatorChar
if (-not $manualTarget.StartsWith($allowedParent, [StringComparison]::OrdinalIgnoreCase)) { throw '清理路径越界' }
if (Test-Path -LiteralPath $manualTarget) { Remove-Item -LiteralPath $manualTarget -Recurse -Force }
'HOST','PORT','VITE_PORT','DATA_DIR' | ForEach-Object { Remove-Item -LiteralPath "Env:$_" -ErrorAction SilentlyContinue }
```

反馈格式：`M编号 / 通过或失败 / 实际现象 / requestId（如有）`。失败时附终端错误码即可，无需提供数据库文件。

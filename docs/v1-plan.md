## 目标

交付可启动的图片审阅 Web 应用：输入昵称 → 上传图片 → 点击标记并填写问题 → 显式保存 → 再次打开继续审阅。支持多图片、多个标记、缩放滚动、编辑删除、重启恢复，以及本机多浏览器访问同一服务的并发协作；局域网部署和第二设备验证延期。

本文汇总产品规则、技术选型、接口草案和阶段路线图，供编写各阶段 spec 时引用；新增参数和交互语义均为建议，待用户对齐。本文不单独进入实施或 completed 生命周期，文档完成不等于功能完成。

### V1 边界

- 一个 Node 服务、一个本地 SQLite 数据库；不通过网络盘共享数据库。
- 昵称和 UUID 是可伪造的操作人标识，不是认证；可信访问者可以查看、修改和删除所有图片与标记。
- 不做账号密码、角色权限、公网部署、生产 HTTPS、多租户、Electron 或安装包。
- 不做 WebSocket、自动保存、自动文本合并、CRDT/OT、Redis、消息队列、分布式锁或多实例。
- 不做图片裁剪、旋转、批注导出、回收站、服务端缩略图或外部 URL 抓图；当前工作台已实现版本历史，明确删除整图时一并清理。
- P6包含SSE已保存更新通知；编辑提示/软锁、自动保存、字段级合并、原图替换和局域网验证仍需单独提案。

### 当前产品规则

1. **提交以完整整图版本为单位，界面支持当前点与全部两种范围**：标点“保存”只提交目标点，其余新增/编辑/待删除保留草稿；顶部“保存全部修改”一起提交。每次有效提交均用整图基线/事务形成完整版本，不拆成多个部分成功。单点未知请求保留原范围/载荷/身份；迟到回执以本次精确历史重建基线，再核对后来更新。上传和整图删除直接提交。
2. 多条标记可以独立展开编辑；导航/切昵称有“保存后继续/放弃/留在当前”。重新加载有草稿时进入核对，读取不替换本地输入。同标签页尽力恢复草稿；普通关闭新开不承诺恢复，缓存失败不影响正式保存，不承诺崩溃或断电恢复。
3. 标记ID在草稿创建时固定；服务端内部编号不复用，页面按有效集合显示连续序号，各历史独立编号。坐标创建后不可拖动，移动通过明确删除重建。
4. 说明 trim 后 1–2000 字符；昵称 trim 后 1–40 字符；严重程度为 low/medium/high，默认 medium；说明以纯文本渲染。
5. V1 支持 PNG/JPEG/WebP 静态图片；暂不支持 SVG、GIF、HEIC、动画或 EXIF 旋转需求。带非正常 EXIF 方向的图片应拒绝并提示先转正，不接受坐标解释不一致的文件。
6. 单张最多 20 MiB、宽高各不超过 12000 像素、总像素不超过 4000 万；一次选择最多 10 张，逐文件请求，分别报告成败，不回滚已成功项。相同内容允许作为不同图片导入。
7. 适应窗口为初始视图，按舞台实际剩余空间水平/垂直居中；缩放10%–400%，舞台/图片栏/标记/图库内部滚动，不由长列表撑高整页。窄屏使用面板切换；点击图外不创建，已有标记只选中并可定位。重复尺寸不触发重新定位，隐藏面板不写无效视图缓存。
8. 进入图片/主动读取、SSE通知及连接建立/恢复/窗口激活时读取正式状态；无草稿可更新，有草稿只提示并进入核对。原基线/我的草稿/最新状态按ID比较，独立修改保留，同标记不同修改人工选择；应用后再点保存，再次过期仍409。不采用无条件最后到达覆盖，不广播输入过程，不轮询。
9. 图片删除需二次确认，并说明其所有标记一并删除。没有撤销能力；旧页面再保存返回 404，不恢复已删图片。

## 技术方案参考

### 技术栈与职责

| 层 | 选择 | 职责与限制 |
|---|---|---|
| 运行环境 | Node 24.x、npm、TypeScript strict | 沿用已安装运行时主版本；P0 锁定依赖及 package-lock.json |
| 前端 | Vue 3、Vite、原生 CSS | 单工作台页面；组件与 composable 管理状态，初版不引入 Router/Pinia/UI 大组件库 |
| 图片舞台 | HTML img + SVG overlay | 相同尺寸与缩放容器；归一化坐标；不持久化视口像素 |
| API | Express 5、REST/JSON | 参数校验、HTTP 状态、requestId、生产静态资源托管 |
| 共享契约 | Zod + TypeScript | 运行时 schema 与推导类型；浏览器不能导入 Node/数据库模块 |
| 数据 | better-sqlite3 + SQL 迁移 | 短事务和参数化 SQL；不引入 ORM；P0 验证 Windows/Node 24 安装与读写 |
| 上传 | Multer 磁盘暂存 + Sharp 元数据校验 | 限额、类型签名、解码/尺寸/方向校验；不把整批图片读入内存 |
| 日志 | Pino | 请求摘要及业务 ID；不输出二进制、请求正文或完整本机路径 |
| 验证 | Vitest、Supertest、ESLint、vue-tsc/tsc 与手动测试 | 覆盖纯逻辑、API/存储集成及静态检查；页面交互由用户按 tests/manual/ 验证，不使用浏览器自动化 |

当前所需依赖已安装并精确锁定，P4 新增 Multer 2.5.0、Sharp 0.35.5 和开发类型 @types/multer 2.3.0；在 Windows/Node 24.18.0 上进行了真实图片解码和文件/API 回归。实际安装清单以 package.json / package-lock.json 为准；后续阶段仍只纳入当时所需依赖。

参考官方资料：[Vite](https://vite.dev/guide/)、[Express 5](https://expressjs.com/en/5x/api/)、[better-sqlite3](https://github.com/WiseLibs/better-sqlite3)。官方说明不能替代本机安装与运行验收。

### 目录和启动链路

```text
src/client/              Vue 页面、组件、composables、API client
src/server/              app/server 入口、路由、服务、数据访问、配置、存储
src/shared/              schema、DTO、错误码；无 Node 专属依赖
migrations/              按版本排序的 SQL 与迁移记录
tests/                  单元/集成测试、配置、辅助代码和 manual/ 手动集合
scripts/                 失败复现等开发脚本
workspace/specs/          本地规格及验证记录，已被 Git 忽略
dist/client/ server/      构建输出，Git 忽略
```

- 开发：Vite 127.0.0.1:5174，代理 /api 到 Express 127.0.0.1:3002；浏览器请求相对 /api 路径。
- 生产：npm run build 后 npm run start；Express 同源提供页面、API 和图片内容，无需运行 Vite。
- 配置：HOST、PORT、DATA_DIR。默认只监听 127.0.0.1:3002；局域网通过 HOST=0.0.0.0 显式开启，不自动修改防火墙。
- DATA_DIR 默认采用 [设计基线](design.md) 的 Windows/macOS/Linux 规则；显式覆盖必须是绝对路径。所有业务 storage_key 由服务端生成且只能解析到数据目录内。
- npm run dev 一并启动前后端并共同退出；build/lint/typecheck/test 由根 package.json 提供。业务阶段再提供 repro:invalid-annotation。测试统一放在 tests/，页面按手动集合验收。

### 数据与文件一致性

沿用 images、annotations 两表；补充 updated_by_name，与 created_by_name 一致保存写入时昵称快照。所有业务 ID 为 UUID，时间使用 UTC ISO 字符串；UI 本地化显示。无账号表。

- annotations：x/y 有限数且在 [0,1] 内；number 正整数、(image_id,number) 唯一；version 从 1 开始，每次成功更新 +1。
- images.next_annotation_number从1开始，创建标记与增加计数同事务完成，不使用客户端max+1；整图保存包含多条写入、版本及回执的原子提交。
- 启用 WAL、foreign_keys、busy_timeout=5000；SQL 约束与共享 schema 双重保护；迁移在启动监听前完成，失败则不启动业务服务。
- 上传：同一 DATA_DIR 暂存 → 校验 → 生成 storage_key 并移动 → 事务写元数据；失败清理。崩溃遗留文件由启动扫描报告；只清理可确认无引用且超过 24 小时的临时/孤儿文件。
- 删除：事务删除图片元数据及级联标记，再清理文件；物理删除失败记录待清理警告，后续扫描清理，API 不再暴露已删除图片。数据库有记录但文件缺失时返回 IMAGE_FILE_MISSING，不伪装成功。
- V1 文档提供停服备份/恢复步骤：备份整个 DATA_DIR；不宣称只复制运行中的 app.db 是有效备份。不提供在线备份 UI。

### API 契约

成功返回 DTO，时间与坐标规则遵循上述定义；错误沿用设计基线的 error.code/message/requestId。响应带 X-Request-Id。未知 API 返回 JSON 404，不回退到前端 HTML。

| 方法与路径 | 输入/结果 |
|---|---|
| GET /api/health | 200，进程存活；不据此宣称数据库正常 |
| GET /api/ready | 检查数据库查询及目录可写；就绪 200，否则 503；不返回绝对路径 |
| POST /api/workbench/users/enter | username及可选已有userId；返回操作人记录，不是认证 |
| GET /api/workbench/images | 图库摘要，支持q、page和sort；每页12条 |
| GET /api/workbench/images/:id | 当前图片、完整标记集合和最新审阅revision |
| POST /api/workbench/images/:id/saves | {requestId,baseRevisionId,userId,markers}；返回保存版本/当前detail/图库摘要；基线过期409，同请求确认不重复写入 |
| GET /api/workbench/images/:id/history | 完整版本索引分页，每页20条 |
| GET /api/workbench/images/:id/history/:revisionId | 所选完整状态与变化；只读 |
| GET /api/events | SSE失效摘要，上传/保存/旧标记API实际提交/整图删除后通知；不提供持久事件回放 |
| POST /api/images | multipart 单个 file；201 返回图片元数据；前端多图逐个调用 |
| GET /api/images/:id | 图片元数据及按 number 排序的 annotations |
| GET /api/images/:id/content | 从受控 storage_key 输出已校验图片和正确 Content-Type |
| DELETE /api/images/:id | 明确确认，JSON {userId,baseRevisionId}；204；已不存在404，旧基线409 |
| POST /api/images/:id/annotations | { id:客户端UUID, x,y,note,severity,actorId,actorName }；201 返回完整标记 |
| PATCH /api/annotations/:id | { version,note,severity,actorId,actorName }；200 返回新版本；不接受更换 image_id/number/坐标 |
| DELETE /api/annotations/:id | JSON { version,actorId,actorName }；204；版本不符 409 |

新增标记的客户端 UUID 在一次草稿生命周期内固定：重复提交同一 ID、同一创建者及同一内容，返回现有记录且不重复分配编号；ID 被不同内容使用则返回 409。服务端须验证 UUID。该最小重复保护不等于自动保存或通用离线同步。

400：空说明、越界坐标、无效字段；404：资源不存在；409：版本过期或重复 ID 内容冲突；413：上传超限；415：不支持的类型；503：数据库繁忙或存储暂不可用；500：未预期故障。分别使用稳定错误码，服务端不把 SQL/堆栈/本机路径返回客户端。

### 前端状态与失败恢复

- 三块区域：图片列表、主图与缩放工具、标记列表/编辑表单。无图片、加载中、上传失败、保存中、失败、冲突分别有可辨识状态。
- 坐标换算 x=(clientX-rect.left)/rect.width，y 同理；rect 必须是实际图片而非含留白的外层容器。服务端拒绝越界，不静默修正错误数据。
- 保存中禁用同一操作的重复点击；失败保留草稿和错误 requestId，允许用户重试。
- 保存响应未知时冻结原业务requestId/载荷/身份，先确认原请求再读取/合并；409时保留输入，通过核对重设基线并使用新业务请求ID。已删标记不由旧草稿恢复，可明确另建新UUID。
- 删除响应丢失先刷新确认存在性，再决定重试；不存在视为已删除。冲突删除不得无条件重试。
- 数据列表在成功响应后更新；没有成功响应不显示“已保存”。未保存草稿不写SQLite，同标签页缓存不等于正式保存。后台GET用读取代次/图片ID/基线检查拒绝晚到覆盖；历史视图不自动跳到新版本。

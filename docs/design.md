# 当前设计

更新：2026-10-27。本文描述当前代码，不保留旧阶段设计草案。运行入口见[README](../README.md)，文件职责见[开发流程](development.md)，验收状态见[测试入口](../tests/README.md)。

## 产品行为

流程为账号密码登录后进入共享图库，上传/打开图片，在工作台浏览或编辑，再查看完整历史版本。

- 图库支持搜索、排序、网格/列表和分页。一次选择1–10张 PNG/JPEG/WebP 静态图，逐文件顺序上传；单张成功自动打开，多张留图库。正常成功显示短提示，部分失败显示摘要与按需详情。结果未知时暂停队列、锁定身份，保留原文件和ID确认；放弃等待不代表服务器取消，队列不承诺刷新续传。
- 打开/切换图片及刷新后默认鼠标模式：左键拖动平移、滚轮按指针位置缩放，只读选择标记。图片点击和Enter/空格不新增，标记没有输入、保存/取消、删除/撤回入口；保存全部禁用。
- 打点模式才允许有效图片区域点击或Enter/空格新增，编辑说明、严重程度和12–48px独立点大小。切换工具保留草稿；拖动不移动标记坐标，不自动保存。已经发出的未知请求可在鼠标模式确认，避免冻结后无法恢复。
- 编辑区“保存”透明底绿字，只提交当前点，保留其他新增/编辑/待删除草稿；“取消”只撤回当前点，新点则移除。顶部“保存全部修改”提交全部净变化。离开、换图和退出登录均保护未保存输入。
- 每次有效保存形成一个固定编号的完整版本；无变化与幂等重试不重复建版本。历史只读、原图单份、图片存续期间历史全部保留。界面按有效集合连续编号，稳定标记ID与内部编号不变。
- 画布按工具条和底栏之间的实际剩余空间居中，适应不强制放大小图，手动缩放10%–400%，实际适应比例可低于10%。底栏左侧版本/保存时间/操作人，右侧原图尺寸。窄屏切换图片/标记/历史面板；短窄窗口内部滚动保持控件可达。
- 明确删除整图会清除本图、标记、版本、回执及相关草稿，需二次确认且不可撤销；同名新上传是独立图片，不继承旧坐标。

说明trim后1–2000字符、昵称trim后1–40字符，均按纯文本渲染。单图最多20MiB、边长各≤12000、总像素≤4000万；动画和非正常EXIF方向拒绝，客户端预检不替代服务端验证。

## 运行拓扑

```text
浏览器 A/B → 开发 Vite 5174 → /api 代理 → Express 3002 → SQLite
                                              └→ 本地原图目录
浏览器 A/B → 生产 Express 3002（页面、API、原图同源）
```

Node.js 24.x、Vue 3/Vite、Express 5、better-sqlite3、Sharp 和 Zod；TypeScript strict，依赖以包清单/锁文件为准。不使用 Electron、ORM、多实例、Redis、消息队列或网络共享SQLite。

默认HOST=127.0.0.1，PORT=3002，VITE_PORT=5174；端口冲突、配置/目录/迁移故障明确失败，不静默切换。开发监督进程共同启动/退出前后端，IPC父通道断开回收自身子进程；生产一个Node进程托管静态构建和API。

## 数据与存储

DATA_DIR 显式设置时必须是绝对路径；默认：

| 平台 | 数据目录 |
|---|---|
| Windows | %LOCALAPPDATA%/ImageReviewAnnotator |
| macOS | ~/Library/Application Support/ImageReviewAnnotator |
| Linux | $XDG_DATA_HOME/ImageReviewAnnotator，未设置则 ~/.local/share/ImageReviewAnnotator |

```text
<DATA_DIR>/
  app.db
  images/<image-id>/original.<ext>
  tmp/uploads/<request-id>.upload
```

SQLite启用WAL、foreign_keys和5000ms busy_timeout。正式SQL在migrations/，按文件名及校验和运行；已应用文件不改写，启动迁移失败不监听。

| 迁移 | 责任 |
|---|---|
| 001 | 初始化基础数据库 |
| 002 | 图片/标记、编号、版本及创建重复保护 |
| 003 | 操作人、工作台完整版本/差量和保存回执 |
| 004 | 独立点大小、固定图片版本号及旧数据兼容 |
| 005 | 整图删除后的最小ID记录，防止旧上传复活 |
| 006 | 受控账号凭证、固定角色与服务端会话 |

数据库存相对storage_key，不存跨平台绝对路径；原图不作为BLOB或每次版本副本。上传经暂存、字节/格式/尺寸校验和正式文件补偿后写元数据。删除先事务完成逻辑删除，再清理文件；失败记录告警，启动扫描只处理确认无引用且超过24小时的本应用文件。SQLite与文件系统不是跨资源原子事务。

备份先停止自己的实例，再复制整个DATA_DIR到另一个受控目录；恢复时也使用完整目录。不要把运行中的单个app.db当作有效备份。演练只用tests/.tmp中的独立副本，不能覆盖真实用户数据。

## 坐标、草稿与版本

图片与SVG标记共用尺寸容器，坐标按实际图片getBoundingClientRect换算并存为[0,1]归一化值，禁止持久化窗口像素。点大小为屏幕像素；缩放不修改原图或标记坐标。ResizeObserver按动画帧合并、过滤相同/隐藏尺寸；浮点适应边界不制造无谓滚动条，视图缓存保存缩放和图像锚点。

已保存基线、当前草稿和展开状态分离；同标签页尽力恢复草稿，普通关闭新开不承诺恢复。缓存失败与后端失败分别提示，不撤销已经完成的保存，也不宣称浏览器强退/物理断电可恢复。

单点和全部保存都复用整图短事务，携带baseRevisionId。请求的业务ID、范围、操作人和载荷在结果未知时冻结；回执与业务变更同事务提交，重试先查回执，再检查基线。HTTP的X-Request-Id是诊断ID，与保存幂等ID不同。图片之后明确删除会清理其回执，旧请求不能重建图片。

## 协作

本机两个独立浏览器通过同一Node服务访问数据。整图基线过期返回409；客户端以旧基线/本地输入/最新状态，按稳定标记ID三方比较：独立修改保留，同点冲突由用户选择整条结果。核对应用后另点保存，再次过期仍拒绝；已删标记只允许显式另建新ID，不采用最后到达覆盖。

SSE仅在提交后通知已保存更新，不广播输入或光标。无草稿读取最新，有草稿/未知请求/核对时保留副本，历史不跳转。连接建立、恢复及窗口激活GET对账；慢连接断开后再对账，不依赖持久事件队列保证写入安全。

## 身份与权限

账号包含唯一 loginName、展示昵称和 member/admin 角色。loginName 为 1–40 字小写 ASCII 字母/数字及点、横线、下划线，首位必须是字母或数字；输入大小写归一化。昵称为 1–40 字，可重复。密码不设业务长度和复杂度限制，允许空字符串、短密码及空格，不 trim；使用异步 scrypt（N=131072/r=8/p=1）和独立随机 salt，只存算法参数与哈希。登录按账号和来源限流，哈希并发有上限。

所有业务读写和 SSE 必须登录；成员可查看共享原图/标记/历史、上传和共同增改删标记，管理员额外可不可撤销地删除整图。登录页支持自助创建普通成员；没有逐图所有权、只读角色或网页账号管理台。角色和操作人从服务端会话读取，不能通过请求自报获得权限；兼容身份字段如存在必须与会话一致。

会话随机 token 放在项目专属 HttpOnly/SameSite=Lax Cookie，数据库只存 token 摘要，24 小时固定有效；HTTPS 设置 Secure。退出撤销当前会话，重置密码、停用或调整角色撤销账号全部会话；SSE 最多 15 秒内检测并关闭。业务响应 no-store。写请求检查精确 Origin 和 X-Expected-User-Id；后者只检测旧标签页身份变化，不授予身份或权限。健康检查和登录页面公开。

本机 HTTP 默认允许当前开发/生产 loopback 来源。APP_ORIGIN 可限定精确来源；非 loopback 监听要求显式 HTTPS 来源，由部署方提供 TLS 反向代理。该配置不代表已验收 LAN、代理或公网部署。

普通成员在登录页注册，昵称可选（留空使用loginName），注册成功后返回登录页且不设置/替换会话Cookie。即使尚无管理员，首个注册者仍是member。服务端注册schema不接受role/userId/enabled/passwordHash，不能通过注册认领旧用户或提升权限。注册独立按来源限制每15分钟5次尝试，使用精确Origin校验、2KiB请求体上限和有界密码哈希并发；请求体上限是资源控制，不是密码强度规则。

维护人通过 `npm run account -- init admin "管理员"` 初始化首个管理员；后台也可用 `create <login> <昵称>` 创建成员，再用role命令提升管理员，UI不能创建管理员或调整角色。reset/disable/enable/role/list/help 维护账号。密码隐藏输入，不支持命令行传密码。部署构建也支持 `node dist/server/account-cli.js`。CLI 仅处理凭证/会话及必要用户记录，不启动原图扫描；首次迁移先停自己的实例并备份。无账号不开放业务，无默认密码或自动首访管理员。

旧 users 不自动成为可登录账号。维护人可在 init/create 后附 `--user-id <UUID>` 明确绑定已经核实的历史用户，保留原昵称和历史关系；保留系统历史用户不可登录，重复昵称需分别建唯一 loginName。绑定不能证明旧记录的真实操作者，不能由浏览器昵称或 userId 自动认领。

浏览器启动向 /auth/me 确认身份，缓存不恢复授权。草稿和视图按 userId＋imageId 隔离，旧匿名草稿不自动导入。会话失效保留原用户输入、暂停上传并返回登录；相同账号重登后由用户继续核对，带未知请求/待处理队列时要求先用原账号恢复。同源 Cookie 在标签页共享，其他标签页换账号时旧页写请求被拒绝；两个不同账号并行审阅应使用独立浏览器配置或隐私窗口。


## 接口与错误

| 路径 | 用途 |
|---|---|
| GET /api/health、/api/ready | 存活与存储就绪 |
| POST /api/auth/register | 自助创建普通成员，不建立/替换登录会话 |
| POST /api/auth/login、GET /api/auth/me、POST /api/auth/logout | 验证凭证、确认当前账号、撤销会话 |
| POST /api/workbench/users/enter | 已停用，410 LOGIN_REQUIRED |
| GET /api/workbench/images | 搜索、排序与分页 |
| GET /api/workbench/images/:id | 当前完整工作台数据 |
| POST /api/workbench/images/:id/saves | 当前点/全部范围经客户端构造后整图原子保存 |
| GET /api/workbench/images/:id/history | 版本列表 |
| GET /api/workbench/images/:id/history/:revisionId | 精确完整历史版本与变化 |
| GET /api/events | 已保存更新通知 |
| POST /api/images | 上传单文件；批量由客户端队列编排 |
| GET /api/images/:id/content | 原图内容 |
| DELETE /api/images/:id | 带基线的整图删除 |

旧GET /api/images/:id和逐条POST /api/images/:id/annotations、PATCH/DELETE /api/annotations/:id仍保留兼容，使用标记version并推进整图历史；不是当前界面的逐条操作协议。

错误为error.code/message/requestId，响应带X-Request-Id；业务 API 先鉴权，已登录未知API返回JSON 404，未登录返回401。用户文案中文，技术日志英文ASCII。错误和日志不包含SQL、堆栈、请求正文或完整本机路径。

## 后续边界

先完成[待验收集合](../tests/manual/current.md)，独立待审缺陷在那里登记。自动保存、细粒度资源权限、软锁/在线编辑提示、字段级合并、原图替换、导出、回收站与LAN部署均需另行讨论和批准spec；不因文档整理提前实现。

当前为单 Node、本地 SQLite，不支持多实例或网络盘共享数据库；LAN 和第二设备尚未验收。SSE 无持久回放，重连通过读取最新状态对账。上传队列保存在内存中，不承诺刷新续传或服务端取消；同名上传是独立资源。图片明确删除后回执也删除，旧请求不能恢复图片；合并连同待删项超过 500 条时拒绝应用并保留草稿。

物理断电、磁盘耗尽和 Windows ACL 实机拒写未专项演练；macOS/Linux 仅有路径规则测试，尚无完整实机运行验收。正常路径、故障注入或自动检查通过不能替代停服备份恢复演练和用户页面验收。实际状态见[测试入口](../tests/README.md)和[当前验收](../tests/manual/current.md)。

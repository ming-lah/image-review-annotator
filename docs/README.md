## spec 的职责

一次开发只维护一份 spec：本次实现什么、具体行为、怎么实现、测试与验收。内容自身完整，不要求需求编号或额外关联文件；避免用目录和依赖清单代替行为需求。

首个 spec 已完成：本地 workspace/specs/completed/2026-10-25-p0-p1-skeleton.md，保留实现结果与失败修复。测试集合统一归入 tests/，spec 只引用。workspace/ 被 Git 忽略，公开仓库不包含本地 spec。

docs/ 中的方案更新不等于阶段实施授权；新增建议也不因归入 docs/ 而变成已确认决定。出现冲突时先修订涉及的方案和阶段 spec，再实施。
